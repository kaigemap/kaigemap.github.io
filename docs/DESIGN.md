# kaigelab デザイン仕様

この文書は、サイトの見た目と動きを決めたものです。実装する人が迷わないように、数値まで書いています。
試作の画像と試作のソースは `~/Downloads/kaigemap-design-spec/` にあります。

- `01-dial-pc-1440.jpg` … PC（1440x900）の静止状態
- `02-dial-pc-1280-first-item.jpg` … PC（1280x800）、1件目を選んでいる状態
- `03-dial-phone-390.jpg` … スマホ（390 幅）の静止状態
- `04-demo-art-soramoyo.jpg` … 録画に使う見本の絵（箱の正面、カード6枚、カードの裏）
- `prototype/` … 上の画像を作った HTML と絵のスクリプト（`site.html`、`art.mjs`）

試作で確かめたのはレイアウト、ダイヤルの形、タイルの見え方、書体、見本の絵です。
動き（ばねの数値）は計算で決めた値で、まだ画面で確かめていません。実装してから 6.9 の手順で調整してください。
試作の画面の中に映っているアプリの動画は古い録画（1120x700、古い見本の絵）のままです。

## 1. いまのサイトの問題と、新しい考え方

### 1.1 いまのサイトがダサい理由

1. **大きなカードを傾けて並べただけになっている。** 隣のカードは斜めに切れた灰色の板にしか見えず、次に何があるか分からない。次を見たくなる理由がない。
2. **置き方に意図がない。** 画面の真ん中にカード、その下に名前、説明、ボタン2つ、点のページャーを縦に積んでいる。テンプレートの並べ方で、余白も上下に等分されているだけ。
3. **文字が多く、どれも同じ強さ。** タグライン、説明、「開く」「コード」、言語4つ、表示切り替え、GitHub。system-ui の太字ばかりで、書体に個性がない。
4. **物としての手ざわりがない。** 枠は角丸の板に影を付けただけ。光も素材もない。黒い太い縁のスマホは安く見える。
5. **録画の中身が悪い。** PC は 1120x700 で狭い。見本の絵（「ランタンループ」の箱、色付きの丸や四角のカード）が雑で、アプリ自体まで雑に見える。
6. **動きが1種類しかない。** ばね1本で全体が横に動くだけで、重さの違いも、止まるときの手ごたえもない。

### 1.2 考え方

**画面の端に、大きなダイヤルが少しだけ見えている。それを回すと、横に置いた PC とスマホの画面が入れ替わる。**

- 円弧のカルーセルは、大きなカードではなく**小さな正方形のタイル（サムネイル）**を並べたダイヤルにする。タイルが小さいので、前後の数件がいつも見える。
- ダイヤルは物として作る。縁に細かい目盛りと番号があり、止まる位置ごとに軽い手ごたえがある。真ん中にはガラスのルーペがあり、その下を通るタイルが少し大きく見える。
- PC の画面とスマホの画面は、ダイヤルの外に、重ねずに置く。ここは動かしすぎない。
- 紙の色の背景、ほぼ白黒、文字はごく少ない。色はタイルの淡い地色と、録画の中身だけが持つ。

### 1.3 2つの参考から何を取るか

- 「レンズの縦スクロール」からは、**紙の色、広い余白、小さな正方形のタイル、端での歪み、ごく小さい文字**を取る。
- bestdesignsonx.com の作例からは、UI は真似しない。**触りたくなる物の感じ（素材、光、奥行き）と、驚きはあるが抑えた動き、1つの案を丁寧に作る姿勢**を取る。

わくわくする感じは、次の2つだけで作る。あれこれ足さない。

1. **ダイヤルの手ごたえ。** 目盛り、止まる位置の引っかかり、針のふるえ、ルーペ（6章）。
2. **タイルが物として反応する。** 光の当たり方が回しても変わらない、ホバーで少し浮く、押すと沈む、速く回すと少し伸びる（3章、6章）。

音、カスタムカーソル、フローティングのドック、検索は入れない。WebGL も使わない（6.8）。

## 2. レイアウト

### 2.1 共通の決まり

- 件数は約13件（アプリ11、Claude Code のスキル2）。端から端まで並ぶ有限のリストにする。**ループさせない。** 端では引っぱると少し伸びて戻る（6.2）。
- PC の画面とスマホの画面は、どの画面幅でも両方見せる。**重ねない。**
- 静止時に見えるもの
  - ダイヤル（タイルが PC で前後4件ずつ、スマホで前後2件ずつ）
  - 選んでいるアプリの PC 画面とスマホ画面（動画が再生中）
  - 番号と年（例 `04 / 13  2024`）、名前、一言説明、作った理由（あれば）
  - 左上に `kaigelab`、右上に言語と一覧の切り替え
- レイアウトの切り替え: **幅 900px 以上、かつ 幅/高さ が 1.2 以上なら「横長」**、それ以外は「縦長」。

### 2.2 横長（1440x900 と 1280x800）

ダイヤルは左端。中心は画面の左の外にあり、右側の縁だけが弧として見える。PC 画面とスマホ画面は右側に並べ、**下端をそろえる**（同じ台の上に置いた物に見せる）。スマホのほうが背が高いので、PC 画面の上に空きができる。そこに名前を置く。

計算式（`W` `H` は表示領域。`W` は 1680、`H` は 1050 を上限にして計算し、超えた分は右と下の余白にする）。

|---|---|---|---|
| 外側の余白 `m` | W ≥ 1400 なら 40、それ未満は 32 | 40 | 32 |
| ダイヤルの半径 `R` | 固定 | 1100 | 1100 |
| ダイヤルの縁の x（いちばん右） `rim` | round(W × 0.122) | 176 | 156 |
| ダイヤルの中心 | (rim − R, H / 2) | (−924, 450) | (−944, 400) |
| ステージの左端 `x0` | round(W × 0.2) | 288 | 256 |
| 下端の線 `ground` | round(H × 0.845) | 760 | 676 |
| スマホ画面の高さ `phH` | round(H × 0.69) | 621 | 552 |
| スマホの外枠の幅 `phW` | phH × 390/844 + 13 | 300 | 268 |
| スマホの外枠の左 | W − m − phW | 1100 | 980 |
| PC とスマホの間 `gap` | round(W × 0.028) | 40 | 36 |
| PC の枠の幅 `pcW` | スマホの左 − gap − x0 | 772 | 688 |
| PC のタイトルバーの高さ `bar` | round(pcW × 0.036) | 28 | 25 |
| PC の枠の高さ `pcH` | pcW × 0.625 + bar | 510 | 455 |
| PC の枠の上 | ground − pcH | 250 | 221 |
| スマホの外枠の上 | ground − phH − 13 | 126 | 111 |

- 名前は1行。`pcW` より長いときは、収まるまで文字サイズを下げる（下限 40px）。
- `kaigelab` は左 `m`・上 28。言語と一覧の切り替えは右 `m`・上 28。
- 高さが 640 未満の横長（低い窓）では、作った理由を出さない。

### 2.3 縦長（390x844）

ダイヤルは下端。中心は画面の下の外にあり、上側の縁だけが弧として見える（親指で回す位置）。
PC 画面は上に幅いっぱい。その下の段は、**右にスマホ画面、左に文字**を置く。

高さは `100svh` を使う（アドレスバーが出ている状態でも収める）。`H` は svh の実寸。

| 値 | 式 | H=760 のとき | H=664 のとき |
|---|---|---|---|
| 余白 `m` | 固定 | 16 | 16 |
| PC の枠 | 左 16、上 58、幅 W − 32、bar 13、高さ 幅 × 0.625 + 13 | 358 x 237 | 358 x 237 |
| 下の段の上 `rowTop` | 58 + pcH + 14 | 309 | 309 |
| ダイヤルの縁の y（いちばん上） `rim` | H − 104 − safe-area-inset-bottom | 656 | 560 |
| スマホ画面の高さ `phH` | min(330, rim − 24 − rowTop − 9) | 314 | 218 |
| スマホの外枠 | 右端を W − 16 にそろえる。幅 phH × 390/844 + 9 | 154 幅 | 110 幅 |
| 文字の列 | 左 16、幅 W − 32 − スマホの幅 − 16 | 188 幅 | 232 幅 |
| 番号と年 | rowTop + 4 | | |
| 名前 | rowTop + 24、32px（長ければ下げる。下限 22px） | | |
| 一言説明 | 名前の下 12、13px、最大3行 | | |
| 作った理由 | 一言説明の下 16、12px、スマホ画面の下端までに収まる行数で切る | | |
| ダイヤル | 半径 620、中心 (W / 2, rim + 620) | | |

- 幅 520px を超える縦長（タブレットの縦など）は、中身を幅 520px にして中央に置く。ダイヤルは画面幅いっぱい。
- 縦長ではページを縦にスクロールさせない（`overscroll-behavior: none`）。

### 2.4 画面が1つしかないもの

- **DiscordPyoko**（スマホ表示が壊れている）: スマホの場所に、同じ大きさの**点線の枠だけ**を置く（1px、点線、`--ink-3`、中は空）。`aria-label` は「スマホの表示は未対応」。文字は出さない。直したら録画して差し替える。これは「放置したものの UI を見直す」という目的にも合う。
- **speak-notify**（画面がない）: 9.6 を参照。PC の場所にターミナルの再現、スマホの場所にスピーカーの板を置く。

## 3. ダイヤル（サムネイルの弧）

### 3.1 形

| | 横長 | 縦長 |
|---|---|---|
| 半径 `R` | 1100 | 620 |
| タイルの一辺 | 72 | 52 |
| タイルの中心の半径 | R − 62 | R − 44 |
| 隣との間隔（弧の長さ） | 98 | 68 |
| 1件あたりの角度 `step` | 98 / 1038 = 0.0944 rad（5.41°） | 68 / 576 = 0.1181 rad（6.76°） |
| 選んでいるタイルの倍率 | 1.3 | 1.3 |
| 見えるタイル | 前後4件ずつ | 前後2件ずつ |
| 目盛り | 縁から内向き。1件ごとに長い線（11px）、その間に短い線4本（5px） | 同じ |
| 番号 | 長い目盛りの内側に `01`〜`13`（8.5px、等幅） | 同じ |

- ダイヤルの面は直径 2R の円（`border-radius: 50%`）。動かさない。色は `--wheel`。縁に 1px の明るい線、外側に影（5.3）。縁から 20px 内側に 1px の溝の線。
- **タイル、目盛り、番号は「スロット」という要素にまとめる。** スロットは大きさ 0 の要素で、ダイヤルの中心に置き、`transform: rotate(θ)` だけで回す。中のタイルは `left: R − 62 − 36px` のように半径方向へずらして置く。こうすると、1フレームに書き換えるのはスロット13個の `transform` だけになる。
  - 横長: θ = 0 が右向き。θ = g(d) × step（d は 3.3 の式）。
  - 縦長: θ = −90° + g(d) × step。タイルは中で 90° 回して正立させる。
- タイルは弧に沿って少し傾く（横長で隣が 5.4°、4件先で 21.6°）。これが「弧」に見える理由なので、打ち消さない。
- **針**: 縁のすぐ外、選んでいる位置に小さな三角（横長は左向き 6x8px、縦長は下向き 8x6px、`--ink`）。位置は固定。回すとふるえる（6.4）。

- 288x288px の WebP（品質 82、1枚 8〜15KB）。`media/tiles/<id>.webp`。新しく作る `tools/record/make-tiles.mjs` が HTML/CSS を描いて撮る。

### 3.3 選んでいるタイルと、端の扱い（レンズ）

`d = i − p`（`p` はダイヤルの表示位置、6.2）、`a = |d|` とする。

1. **ルーペ。** 選ぶ位置に、固定のガラスを置く。大きさは タイルの一辺 × 1.3 + 10（横長 104px、縦長 78px）、角丸 27%。下を通るタイルは近づくほど大きくなる。
   - 倍率 = 1 + 0.3 × cos²(a × π / 2)（a < 1 のとき。それ以外は 1）
2. **ルーペの縁で少し縮む。** 進む方向の倍率に (1 − 0.10 × sin²(π × a)) を掛ける（a < 1）。ガラスの縁を通るときに像が詰まって見える。
3. **隣を押しのける。** 角度に使う値を g(d) = d + 0.11 × sin(π/2 × clamp(d, −1, 1)) にする。選んだタイルが大きい分、隣が 11px ほど離れ、すき間がそろう。
4. **端で沈む。** 横長は a が 3.2 から 4.8、縦長は 1.8 から 2.9 の間で、進む方向の倍率を 1 → 0.65、不透明度を 1 → 0 にする（どちらも smoothstep）。傾きと合わさって、筒の向こうへ回り込むように見える。
5. **端のぼかし。** ダイヤルの両端に、紙の色から透明へのグラデーションの要素を重ねる（横長は上下に高さ 110px、縦長は左右に幅 56px）。`mask` は使わない（毎フレームの描き直しを避ける）。

ルーペの作り方（CSS だけ。`backdrop-filter` は使わない）。

```css
.loupe {
  border-radius: 27%;
  background: linear-gradient(135deg, rgba(255,255,255,.55) 0%, rgba(255,255,255,.08) 34%,
              rgba(255,255,255,0) 62%, rgba(255,255,255,.22) 100%);
  box-shadow:
    inset 0 0 0 1px rgba(255,255,255,.85),      /* ガラスの縁 */
    inset 0 2px 3px rgba(255,255,255,.9),        /* 上の反射 */
    inset 0 -3px 6px rgba(40,30,10,.10),         /* 下の厚み */
    inset 2px 0 0 rgba(90,170,255,.10),          /* 色のにじみ（青） */
    inset -2px 0 0 rgba(255,120,90,.10),         /* 色のにじみ（赤） */
    0 0 0 1px rgba(28,27,24,.16),
    0 3px 5px rgba(50,40,20,.12),
    0 14px 28px -8px rgba(50,40,20,.30);
  pointer-events: none;
}
```

試作ではガラスが少し弱く見えた。実装では上の値（試作より反射を 1 割強めた値）から始め、画面で見て決める。

### 3.4 タイルの素材と光

- 角丸 22%。厚みを付ける: `inset 0 1px 0 rgba(255,255,255,.55)`（上の縁の光）、`inset 0 -2px 0 rgba(0,0,0,.07)`（下の縁の陰）、`0 1px 1px rgba(50,40,20,.10), 0 5px 10px -3px rgba(50,40,20,.22)`（落ち影）。
- **光は左上から。回しても向きを変えない。** タイルの上に光の層（`linear-gradient(140deg, rgba(255,255,255,.34), rgba(255,255,255,0) 42%, rgba(0,0,0,.05))`）を重ね、スロットの回転と逆に `rotate(−θ)` を掛ける。層はタイルの 150% の大きさにして、回しても角が欠けないようにする。
- ホバー（マウスのみ）: 1.07 倍に浮く。深い影の層（`0 12px 22px -6px rgba(50,40,20,.34)`、ふだんは不透明度 0）を 1 にする。光の層がポインターの位置へ最大 6px 寄る（`transform` で動かす）。
- 押す: 0.94 倍に沈む。深い影を 0 に戻す。
- タイルは `<button>`。`aria-label` はアプリ名、選んでいるものに `aria-current="true"`。押すとその位置まで回る。

## 4. 文字

### 4.1 書体

| 用途 | 書体 | 置き場所 |
|---|---|---|
| アプリ名、`kaigelab` | **Young Serif** Regular 400（OFL 1.1） | `fonts/YoungSerif-Regular.woff2`。ラテン文字だけに絞る（約 25KB） |
| 番号、年、URL、目盛りの数字 | **IBM Plex Mono** Regular 400（OFL 1.1） | `fonts/IBMPlexMono-Regular.woff2`。英数字と記号だけに絞る（約 15KB） |
| 一言説明 | 端末のゴシック体 | `-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Yu Gothic UI", "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans JP", "Noto Sans KR", "Segoe UI", sans-serif` |
| 作った理由 | 端末の明朝体・セリフ体 | `"Hiragino Mincho ProN", "Yu Mincho", "Noto Serif JP", "AppleMyungjo", "Batang", "Iowan Old Style", Georgia, serif` |

- Young Serif は丸みと重さのあるセリフ体で、動きの「むちむち」と合う。試作で実物を確かめた。細いセリフ体（Baskerville で代用）とも比べた。細いほうは上品だが、どこにでもある感じになったので Young Serif にした。大きくしすぎず、静かさを保つ。
- IBM Plex Mono は試作では端末の等幅書体で代用した。実物での確認が要る。
- 日本語と韓国語の書体は同梱しない（1書体で数 MB になるため）。アプリ名はすべてラテン文字なので、同梱の2書体で足りる。
- どちらも `font-display: swap`。Young Serif は `<link rel="preload" as="font" crossorigin>` を付ける。`fonts/` に OFL の全文を `OFL.txt` として置く。

### 4.3 文字が出る場所と、消すもの

残す文字は、アプリ名、番号と年、URL、一言説明、作った理由、`kaigelab`、言語の記号の7つだけ。

| いまあるもの | どうするか |
|---|---|
| タグライン「つくった小さな道具」 | 消す。`<title>` は `kaigelab` だけにする |
| 「開く」ボタン | 消す。**PC の枠のバーにある URL** がリンクになる（`kaigemap.github.io/hakogazou ↗`）。`aria-label` は「hakogazou を開く」 |
| 「コード」ボタン | 消す。一言説明の行の右に `</>` のアイコン（14px、線 1.4px）。`aria-label` は「ソースコード」。リポジトリが非公開のものには出さない |
| 点のページャーと矢印 | 消す。ダイヤルが代わりになる |
| `JA EN ES KO` の4つ | 現在の言語の記号1つにする。押すと4行のメニュー（日本語 / English / Español / 한국어）が出る。`aria-label` は「言語」 |
| 円弧 / 一覧のアイコン2つ | アイコン1つにする。いまと反対の表示のアイコンを出す。`aria-label` は「一覧で見る」「ダイヤルで見る」 |
| 右上の GitHub アイコン | 消す（アプリごとの `</>` で足りる） |
| 再生 / 一時停止のボタン | ふだんは出さない。PC の画面かスマホの画面を押すと止まり、もう一度押すと動く。`prefers-reduced-motion` のときだけ、PC の枠の右下に再生のアイコンを出す |

`aria-label` と一言説明は4言語で持つ（`js/i18n.js`）。

## 6. 動き

動かすのは `transform` と `opacity` だけ。レイアウトや影の値、`filter` は毎フレーム変えない。

### 6.1 言葉を動きに直す

| 言葉 | 具体的な動き |
|---|---|
| 静かに | 大きな画面（PC・スマホ）はほとんど動かさない。入れ替わるときに 56〜84px だけずれて重なって消える。派手に動くのは小さなタイルだけ |
| ぬるぬる | 入力はすべて1つの位置 `p` に流れ、ばねで追う。途中で別の入力が来ても、位置と速度を引き継ぐ。時間で決まるアニメーションは使わない |
| むちむち | 止まるときに 5% だけ行きすぎて戻る。速く回すとタイルが進む方向に最大 10% 伸び、止まると縮んで戻る。押すと沈み、離すと跳ね返る。端では引っぱると伸びて戻る |
| 物の手ごたえ | 止まる位置に引っかかりがある。針がふるえる。層ごとに重さが違う（タイルは軽く、PC 画面は少し遅れ、スマホ画面はもっと遅れる） |

### 6.2 位置とばね

位置の単位は「件」。`p = 0` が1件目、`p = N − 1` が最後。

ばねは `a = (−k × (x − 目標) − c × v) / m` を、1/120 秒きざみの半陰的オイラー法で積分する（1フレームの経過時間は 1/20 秒まで）。すべて `m = 1`。

| ばね | k（硬さ） | c（減衰） | 減衰比 | 使う場所 |
|---|---|---|---|---|
| 止まる | 170 | 18 | 0.69 | 離したあと、キー、タイルを押したとき。行きすぎ 約5%、約 0.45 秒で落ち着く |
| ホイールを追う | 260 | 32 | 0.99 | ホイールとトラックパッドで動かしている間。行きすぎない |
| PC 画面の層 | 120 | 19 | 0.87 | `p` を追う。少し遅れる |
| スマホ画面の層 | 90 | 15 | 0.79 | `p` を追う。もっと遅れて、少し行きすぎる |
| 伸び縮み | 300 | 20 | 0.58 | 速度の大きさを追う。止まったときにぷるっと戻る |
| ホバーと押す | 320 | 22 | 0.62 | タイルの倍率 |
| 針 | 900 | 24 | 0.40 | 針の角度 |

- 止まった判定: 目標との差が 0.0004 件未満、速度が 0.002 件/秒未満。そうなったら位置を目標に合わせ、`requestAnimationFrame` を止める。
- **ドラッグ**: 指に 1:1 で付いてくる。
  - ダイヤルの上: Δp = −(進む方向の移動 px) / 間隔（横長 98、縦長 68）。
  - PC・スマホ画面の上: Δp = −(移動 px) / 220。
  - 進む方向は、横長が縦、縦長が横。6px 動くまではドラッグにしない。
- **離したとき**: 直前 80ms の動きから速度 v（件/秒、±14 で切る）を出す。行き先は round(p + v × 0.18)。ドラッグを始めた位置から ±3 件まで、かつ 0〜N−1 の範囲に収める。速度 v を持ったまま「止まる」ばねに渡す。
- **端のゴム**: 範囲の外に x 件出たとき、表示は sign × 1.2 × (1 − 1 / (|x| × 0.55 / 1.2 + 1)) 件にする。いくら引いても 1.2 件までしか出ない。離すと「止まる」ばねで端に戻る。キーとホイールでは端の外に出ない。
- **止まる位置の引っかかり**: ダイヤルを描くときだけ、表示位置を p′ = p − 0.045 × sin(2π × p) にする。止まる位置の近くではゆっくり、間では速く動き、ノッチのある物を回している感じになる（ずれは最大 4.4px）。PC・スマホ画面の層には使わない。

### 6.3 ホイールとキー

- **トラックパッド**（`deltaMode === 0` で |deltaY| < 50）: 目標 += deltaY / 160（160px で1件）。「ホイールを追う」ばねで追う。130ms 入力がなければ、近い整数を目標にして「止まる」ばねに切り替える。そのとき、動き始めから 0.15 件以上同じ向きに進んでいたら、その向きの整数にする（戻らない）。
- **段のあるマウスホイール**（`deltaMode === 1`、または |deltaY| ≥ 50）: 1回につき ±1 件。90ms 以内の続きは無視する。「止まる」ばねで動く。
- 横長では縦のホイール、縦長の画面でトラックパッドを使うときは縦横どちらでも受ける。`ctrlKey` 付き（拡大）は受けない。
- **キー**: `↑` `←` で前、`↓` `→` で次、`Home` `End` で端。タイルにフォーカスがあるとき `Enter` でそのタイルへ回る。フォーカスの輪は `2px solid var(--ink)`、外側 3px。

### 6.4 タイル、針

- **伸び縮み**: e = min(|v| × 0.012, 0.10) を「伸び縮み」ばねで追う。タイルの倍率は、進む方向が 1 + e、直交する方向が 1 − e / 2。3.3 の倍率に掛ける。
- **針**: 表示位置 p′ がいちばん近い整数をまたぐたびに、針の角速度に ∓220° / 秒 × min(1, |v| / 4) を足す（回す向きと逆へ弾かれる）。「針」ばねで 0° に戻る。振れは最大で 7° ほど。回転の軸は針の根元。
- スロット1個の `transform` は `rotate(θ)`、タイルは `scale(sx, sy)`、光の層は `rotate(−θ) translate(lx, ly)`。

### 6.5 選んだものが入れ替わるとき

PC 画面の層の位置を `ps`、スマホ画面の層の位置を `pp`（それぞれのばねで `p` を追う）とする。アプリ i について `ds = i − ps`、`dp = i − pp`。

| 要素 | 動き |
|---|---|
| PC の枠 | 進む方向に ds × 56px。倍率 1 − 0.03 × min(|ds|, 1)。横長では ds × 1.2° 回す（軸は枠の左の中央）。不透明度 1 − smoothstep(0.25, 0.75, |ds|) |
| スマホの枠 | 進む方向に dp × 84px。倍率 1 − 0.03 × min(|dp|, 1)。不透明度は同じ式を dp で |
| 名前 | 進む方向に ds × 28px。不透明度 1 − smoothstep(0.15, 0.5, |ds|) |
| 番号と年 | 数字だけ差し替える。不透明度は名前と同じ |
| 一言説明、作った理由 | 動いている間は不透明度 0。止まって 120ms 後に、260ms かけて 0 → 1（`ease-out`）。位置は動かさない |

- 進む方向は、横長が縦、縦長が横。
- `|d| < 1` の枠だけ `visibility: visible` にする。同時に見える枠は最大2組。
- 層ごとに動く距離が違う（タイル 98px、スマホ 84px、PC 56px、名前 28px）ので、奥行きがあるように見える。

### 6.6 動画

- ポスター（`<img>`）を下に、`<video>` を上に重ねる。ポスターは動画の最初のフレームと同じ絵にする（8章）。そのため、切り替わりが見えない。
- 選ばれて止まった（速度 0.05 件/秒未満が 120ms 続いた）ら、`currentTime = 0` にして `play()`。`playing` が来たら、動画の不透明度を 280ms で 0 → 1。
- 選択から外れた（|ds| > 0.5）ら、動画の不透明度を 160ms で 0 にし、終わったら `pause()`。
- 同時に再生するのは、選んでいるアプリの PC とスマホの2本だけ。
- 読み込み: 選んでいるアプリの2本は `preload="auto"`。止まって 600ms たったら、次の1件の2本も読み込む。それ以外は `src` を付けない。
- 動画ファイルは、PC の枠の表示幅が 500px 未満なら小さい版（`-s`）を使う（8.1）。
- `muted`、`loop`、`playsinline`。画面を押すと止まり、もう一度押すと動く。

### 6.7 開いたとき

1回だけ。合計 0.8 秒以内。

1. ダイヤルは p = −1.2 から 0 へ「止まる」ばねで回る（タイルが転がって入ってくる）。`#<id>` があればその位置へ。
2. PC の枠は 20px 下・不透明度 0 から、ばね（k 140、c 20）で定位置へ。スマホの枠は 70ms 遅れて同じ動き。
3. 名前と文字は 6.5 の決まりどおり、止まってから出る。

### 6.8 動きを減らす設定、性能

**`prefers-reduced-motion: reduce` のとき**

- ばねを使わない。位置はすぐ目標に移る。入れ替わりは不透明度だけ（150ms）。
- 伸び縮み、針のふるえ、止まる位置の引っかかり、開いたときの動き、光の追従をやめる。ルーペの拡大（静止した倍率）とホバーの影は残す。
- 動画は自動で再生しない。ポスターを出し、PC の枠の右下に再生のアイコン（28px の丸）を置く。
- ドラッグは指に付いてくる（操作そのものなので残す）。離したら目標へすぐ移る。

**性能**

- `will-change: transform` はスロット13個と、見えている枠（最大2組）だけに付ける。
- ダイヤルの入れ物に `contain: layout paint`。
- タイルの画像は 288px の WebP。動画は同時に2本。
- スクロールや `pointermove` のハンドラーでは値を記録するだけにし、DOM への書き込みは `requestAnimationFrame` の中で1回にまとめる。
- **WebGL は使わない。** 動かす物はタイル13個と枠2組で、`transform` で足りる。本物の屈折を WebGL で描くと、動画をテクスチャに毎フレーム送ることになり、スマホで重くなる。CSP とライブラリの同梱の手間にも見合わない。SVG の `feDisplacementMap` も、Safari で遅いので使わない。

### 6.9 実装後の調整の手順

1. `?debug=1` で、ばねの k と c をスライダーで変えられるようにする（公開前に外す）。
2. スマホの実機（iPhone と Android を1台ずつ）で、ダイヤルを速く回す・ゆっくり回す・端で引っぱるの3つを試す。
3. 「止まる」ばねの行きすぎが目につくなら c を 20 に上げる。物足りないなら 16 に下げる。伸び縮みの 0.012 と上限 0.10 は、気づくか気づかないかの強さにする。
4. Chrome の Performance で、回している間に Layout と Paint が出ていないことを確かめる。

## 7. 一覧と、作った理由

### 7.1 一覧（壁）

ダイヤルの代わりに、全部を縦に並べたページ。**全部の画面が小さく動いている**のが見どころ。ページは普通に縦スクロールする。

- 1件 = PC の枠とスマホの枠の組（下端をそろえる、重ねない）と、その下の文字。
- 組の中の割合: PC の枠の幅 70%、すき間 4%、スマホの枠の幅 26%。組の高さはスマホの枠の高さ。
- **偶数番目は左右を入れ替える**（スマホが左）。並びにリズムが出る。
- 文字: 番号と年（10px、等幅）、名前（Young Serif 20px）、一言説明（12px）、作った理由（明朝 12px、最大3行）。`</>` は名前の行の右。

| | 列 | 組の幅 | 列の間 | 行の間 | 上の余白 |
|---|---|---|---|---|---|
| 1440 | 3 | 421 | 48 | 72 | 96 |
| 1280 | 3 | 373 | 48 | 64 | 88 |
| 900〜1199 | 2 | (W − 2m − 48) / 2 | 48 | 64 | 88 |
| 390 | 1 | 358 | — | 48 | 72 |

- 動画は小さい版を使う。表示領域に入っている組のうち、中央に近い順に**横長は3組、縦長は1組**だけ再生する（`IntersectionObserver`）。ほかはポスター。マウスを乗せた組は必ず再生する。
- 組を押すと、ダイヤルの表示に戻り、そのアプリが選ばれる。
- 切り替えの動き: View Transitions API を使う。選んでいるアプリの PC の枠とスマホの枠に `view-transition-name` を付け、一覧の中の同じアプリの組へ移す。ほかは 200ms のクロスフェード。時間は 480ms。イージングは 6.2 の「止まる」ばねを写した次の値。

```css
--spring: linear(0, .065, .212, .389, .564, .717, .839, .929, .989, 1.026, 1.044, 1.049,
                 1.047, 1.04, 1.031, 1.022, 1.015, 1.008, 1.004, 1.001, 1);
```

- View Transitions がないブラウザと、動きを減らす設定のときは、すぐ切り替える。
- `?view=grid` と、前回の表示の記憶（`localStorage`）はいまのまま残す。

### 7.2 アプリごとのページ

**いまは作らない。** カルーセルと一覧で足りる、という決定による。作ることになったら、URL は `?w=<id>` にする（`/<id>/` はアプリ本体が使っているため）。

### 7.3 作った理由

見出しやラベルは付けない。**明朝体（セリフ体）と灰色で、説明と区別する。** 美術館の作品の横にある札のような扱い。

- 出る場所
  - ダイヤルの表示（横長）: PC の枠の下、右寄り（2.2）。最大3行。
  - ダイヤルの表示（縦長）: 一言説明の下（2.3）。入る行数だけ。
  - 一覧: 文字のいちばん下。最大3行。
- 行数を超える分は `-webkit-line-clamp` で切る。全文は `title` には入れない（スマホで読めないため）。**書く長さを守る**ことで収める。
- 形式
  - 本人が書く。Claude は書かない。下書きを出すなら、README とコミットにある事実だけから書き、本人に確かめてもらう。
  - 1〜2文。**日本語で 70 字まで**（横長で3行に収まる長さ）。英語とスペイン語は 150 字まで、韓国語は 80 字まで。
  - 一人称の普通の文。「〜が面倒だったので作った。」「〜のときに使っている。」のように、言い切る。
  - まず日本語を書く。ほかの言語は、日本語が決まってから直訳する。訳がない言語では日本語を出さず、何も出さない。
- データ: `js/apps.js` の各アプリに `year: 2024` と `why: { ja: '', en: '', es: '', ko: '' }` を足す。`why` が空なら、その場所には何も描かない（空きのままでよい）。
- `year` は最初に公開した年。GitHub のリポジトリの作成日から拾い、本人が確かめる。

## 8. 録画

### 8.1 大きさと画質

| | PC | スマホ |
|---|---|---|
| 表示領域 | **1440x900**（いまは 1120x700） | 390x844 |
| DPR | 2（2880x1800 で撮る） | 3（1170x2532 で撮る） |
| 出力 | `<id>.mp4` 1600x1000 と `<id>-s.mp4` 960x600 | `<id>-phone.mp4` 600x1298 |
| CRF | 26（大）、28（小） | 27 |
| 共通 | H.264 High、`-preset slow`、`-tune animation`、30fps、`yuv420p`、`+faststart`、音なし、`-maxrate 1500k -bufsize 3000k` | 同じ |
| ポスター | `<id>.jpg` 1600x1000、`<id>-s.jpg` 960x600（`-q:v 4`） | `<id>-phone.jpg` 600x1298 |

- 1440x900 にする理由: ノート PC の普通の広さで、どのアプリも横に余裕のあるレイアウトになる。ステージの PC の枠は最大 772px 幅なので、Retina でも 1600 幅で足りる。
- PC の枠の中の文字は小さくなる（14px の文字が 7.5px ほど）。PC 画面はレイアウトと動きを見せる役、文字まで読める大きさはスマホ画面が受け持つ、と割り切る。
- いまの動画は 1280x800 で 100〜230kbps。同じ設定で 1600x1000 にしても 1本 300〜600KB の見込み。
- 13件の合計は、リポジトリに 12〜17MB。1回の訪問で読むのは、書体 40KB、タイル 13枚で 150KB、選んでいるアプリと次のアプリのポスターと動画で、最初の表示は 1.5MB 以内に収める。
- `cdp.mjs` の `stopRecording` に、出力を2つ作る指定（`outputs: [{ suffix: '', width: 1600 }, { suffix: '-s', width: 960 }]`）を足す。

### 8.2 長さとループ

- 1本 8〜12 秒。
- **最初と最後を同じ状態にする。** 録画を始める前に `prepare()` で見本のデータを読み込ませ、見栄えのする状態から始める。操作をして、最後に元の状態へ戻す。カーソルと指も最初の位置へ戻す。
- つなぎ目は、最後の 0.4 秒を最初の 0.4 秒へクロスフェードして消す。次のコマンドで確かめた（`T` は元の長さ、`offset` は `T − 0.8`）。

```sh
ffmpeg -i in.mp4 -filter_complex "[0]split[a][b];\
[a]trim=start=0.4,setpts=PTS-STARTPTS[m];\
[b]trim=end=0.4,setpts=PTS-STARTPTS[h];\
[m][h]xfade=transition=fade:duration=0.4:offset=$(echo "$T - 0.8" | bc),format=yuv420p" \
  -c:v libx264 -crf 26 -an out.mp4
```

- ポスターは、ループにしたあとの動画の**最初のフレーム**から作る（いまは途中のフレーム）。サイトで動画が始まるときに絵が飛ばない。
- BrowserSenkou のように動きがないものは、静止画だけでよい。煙など少しでも動きがあるなら 6 秒の動画にする。

### 8.3 カーソルと指

| | いま | これから |
|---|---|---|
| PC のカーソル | 26px の黒い矢印、白フチ | 20px の黒い矢印、白フチ 1.25px、影 `0 1px 2px rgba(0,0,0,.3)` |
| クリック | 青い丸が広がる | 輪だけ。直径 28 → 44px、線 1.5px、`rgba(28,27,24,.3)`、350ms で消える。塗らない |
| 動き方 | — | 1回の移動は 500〜900ms。出だしと終わりをゆっくりにする（`easeInOutCubic`）。止まってから 150ms 待って押す |
| スマホの指 | 44px の灰色の丸 | 36px の丸、`rgba(20,20,20,.18)`、白 80% のフチ 1.5px。押している間は 0.85 倍で `rgba(20,20,20,.3)` |

### 8.4 そのほか

- 外の画像を読むデモ（Auto Max Width）は、`Fetch.enable` で要求を横取りして、手元の見本の絵を返す。実在のアカウントの画像（いまは GitHub のアバター）を使わない。

- 画面に個人の情報（本物の Dropbox のファイル名、Discord の本物の名前、手元のパス）を出さない。

## 9. 録画の中に映す見本

### 9.1 考え方

いまの見本がダサい理由は、ぼかしたグラデーションの丸と、中央に置いた太いゴシックの題名、原色の丸や四角だけのカードだから。**設計された印刷物に見えない。**

これからは、**架空のボードゲームを1つ決め、全部のアプリでそれを使う。** 試作 → カード → 箱 → 告知 → 頒布、という実際の作業の流れを、サイト全体で1本の話にする。

- hakogazou … 箱
- zatsucard … テストプレイ用のカード（文字だけ）
- udocards … 仕上がったカードの山札
